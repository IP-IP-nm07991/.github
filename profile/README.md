<h2>三项要素，顺序不能反</h2>
<p>买住宅 IP 主要看什么？答案可以浓缩成三项：类型对不对、独享不独享、稳不稳定。三项按顺序判断，前面的不成立，后面就不用看了。很多人反过来做，先比价格再看类型，结果在便宜的资源里挑一个勉强能用的，之后反复返工。</p>
<p>顺序本身就是筛选逻辑。用对顺序，能省掉大量无效比较。</p>

<h2>类型为什么排第一</h2>
<p>因为类型是硬属性，改不了。独享程度可以靠加钱换，稳定性可以靠换供应商换，但一条机房地址永远变不成住宅地址。类型不对，后面所有投入都是在错误的基础上做优化。</p>
<p>判断类型不要只看商家怎么写，要看注册库怎么标。查 ASN 归属、运营商名称、反向解析三项，联合判断比单看一项可靠。</p>

<h2>独享为什么排第二</h2>
<p>因为它决定了问题的可归因性。共享地址上，别人的行为会影响你的评分，而你不知道；出了问题，你无法判断是自己的操作还是他人的行为。这种不可归因的状态，会让排查变成无休止的猜测。</p>
<p>验证方式有三个：观察是否有陌生会话痕迹、速度是否稳定、高峰期是否明显衰减。三项都正常，基本可认为独享。</p>

<h2>稳定性为什么排第三</h2>
<p>因为它可以通过运维缓解。掉线可以配置重连、可以准备备用、可以错峰使用。而类型和独享程度，一旦买错，只能换供应商。</p>
<p>但稳定性排第三不等于不重要。它是日常体验的基础，只是它在判断顺序上靠后，因为前两项决定了它是否有意义。</p>

<h3>带宽应该排在哪</h3>
<p>排在稳定性之后。多数店铺运营的带宽需求不高，瓶颈通常在上传。把预算堆在带宽上，往往换不来体验提升，不如花在独享与稳定性上。</p>
<h3>价格应该排在哪</h3>
<p>排在最后。因为前三项是刚性条件，不满足就没有讨论意义。先比价，等于把刚性条件交给价格去筛。</p>

<h2>三项之外的加分项</h2>
<p>一是保号机制。续费能否拿到同一条地址，决定长期运营的连续性。二是更换政策。出问题时多久能换、是否免费，决定处置空间。三是能否提供段信息。愿意提供的，来源通常清楚。</p>
<p>三项加分项不改变判断，但影响长期体验。尤其是第二项，在真正出问题时价值最高。</p>

<h2>落地清单</h2>
<p>第一步，拿到候选资源，先查类型三项。第二步，类型过关的，做独享验证。第三步，独享过关的，连续监测两周看稳定性。第四步，三项都过的，才进入价格比较。第五步，选定后确认保号与更换条款。</p>
<p>五步顺序固定，不要跳。跳过任何一步，都会在后面的环节以返工的形式补回来。</p>

<p>把关注点收成三条就够：类型是否可验证、带宽是否写进合同、更换是否有规则。三条之外的宣传词，多数只是话术。真正决定长期体验的，是这三条能不能落到纸面，而不是首月价格低多少。</p>
<h2>常见问答</h2>
<h3>类型能改吗</h3>
<p>不能。类型由地址的注册属性决定，软件层面无法改变。这是它排第一的原因。</p>
<h3>独享能验证吗</h3>
<p>可以间接验证。观察陌生会话、速度稳定性、高峰期衰减三项，都正常基本可认为独享。</p>
<h3>稳定性多久能测出来</h3>
<p>建议两周以上。单日测试看不出规律，很多问题在第二周才显现。</p>
<h3>价格差很多怎么办</h3>
<p>先看差在哪：类型、独享程度、地区稀缺度、还是服务内容。逐项拆开比，才能看出贵在哪。</p>
